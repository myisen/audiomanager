## 1. 术语表

| 术语 | 定义 |
|---|---|
| 音频库 | 用户在本机指定、纳入管理的一个或多个根目录的集合 |
| 被管理目录 | 位于音频库内、由本软件扫描并生成播放清单的目录 |
| 播放清单 | 与一个被管理目录一一对应、包含该目录内音频文件的有序列表 |
| 播放位置 | 某个音频文件上的已播放秒数，以及该文件是否已播完 |
| 续播点 | 用于恢复播放的（清单、文件、播放位置）三元组 |
| 设备（对端） | 运行本软件、可与本机发生传输的另一台终端 |
| 传输任务 | 一次音频文件在两端之间移动的执行单元 |
| 中继 | 当两端无法建立直连时，代为转发数据的服务 |
| 元数据记录 | 一条音频文件的标题、艺人、专辑、曲序、封面、时长、指纹等描述信息 |
| 同步源 | 提供元数据的外部来源或本地文件来源 |
| 服务模式 | Linux 端不启动图形界面、以系统服务方式运行的运行形态 |
| 分享 | 将本端播放清单或单个音频文件显式标记为对已配对设备可见且可下载的状态 |
| 清单级分享 | 开启后该清单内全部文件对已配对设备可见且可下载 |
| 文件级分享 | 在未开启清单级分享时，单独将某个文件标记为对已配对设备可见且可下载 |

## 2. 背景与目标

### 2.1 观察到的现状与问题

用户在多个设备上持有同一批音频文件，当前处理方式存在以下具体问题：

1. 跨终端搬运音频依赖 U 盘、网盘或数据线，操作繁琐，且无法在设备离线时排队等待。
2. 音频文件按文件夹存放，但大多数播放器需要手工建清单或一次性导入，目录新增文件后清单不会自动跟上。
3. 长音频（有声书、播客、讲座录音）播放中断后，重新打开会从文件开头开始，用户必须手动拖动进度条。
4. 元数据散落在文件内嵌标签、各播放器各自的本地库、以及外部数据库中，同一首曲子在不同设备上显示的名称和封面不一致。
5. Linux 设备常作为长期在线的媒体主机使用，但没有图形界面，通用播放器无法在该环境下被管理或自动续播。

### 2.2 产品决策

对应的产品回应：

| 问题 | 产品决策 |
|---|---|
| 跨终端搬运困难 | 内置 P2P 传输：局域网内自动发现并直连；无法直连时经中继转发；支持断点续传与离线排队；仅分享的清单或文件可被对端浏览与下载 |
| 清单需要手工维护 | 为每个被管理目录自动生成并持续维护一个播放清单，按文件名排序 |
| 长音频无法续播 | 内置播放器持续记录播放位置，重新打开清单时从上次暂停的位置自动继续播放 |
| 元数据不一致 | 内置元数据同步：以内嵌标签与音频指纹为基础，按用户选择的同步源补全与对齐 |
| Linux 无图形界面 | 提供无图形化的服务模式，可被系统托管并按同一套清单与播放位置规则运行 |
| 许可与合规 | 全产品以 MIT 协议开源，并约束内置组件与同步源的许可兼容性 |

### 2.3 目标（可观察）

- 用户可以把一个音频文件从任一端发送到任一对端，接收方在文件到达后直接看到该文件，且该文件落入所属目录的清单。只有用户显式开启分享的清单或文件才可被对端浏览与下载。
- 用户打开任一播放清单，播放器从上次暂停的位置继续播放，无需手动定位。
- 用户在一次元数据同步后，同一个音频文件在各终端上显示的标题、艺人、专辑、封面一致。
- 用户在无图形界面的 Linux 上启动服务后，无需登录桌面即可完成扫描、清单维护、播放与续播。

本文档不设定量化指标（如传输速度、同步命中率），原因：当前无可用基线数据。量化目标将在首次用户测试后根据基线数据补充。

## 3. 产品范围

### 3.1 P0（必须完成，构成最小完整闭环）

| 编号 | 能力 | 说明 |
|---|---|---|
| P0-1 | 本地音频库与目录扫描 | 指定根目录，识别音频文件，建立目录结构 |
| P0-2 | 播放清单自动生成与维护 | 每个被管理目录一个清单，按文件名排序，随目录变化更新 |
| P0-3 | 内置音频播放器 | 播放/暂停/上一首/下一首/进度跳转/音量 |
| P0-4 | 播放位置记忆与续播 | 记录位置并在重新打开清单时自动续播 |
| P0-5 | 设备发现与配对 | 局域网自动发现；跨网络可手动添加并配对 |
| P0-6 | P2P 传输 | 直连优先、中继兜底、断点续传、离线排队 |
| P0-7 | 元数据同步 | 内嵌标签为基础，MusicBrainz / Last.fm / ListenBrainz / 本地播放器库文件为来源 |
| P0-8 | Linux 服务模式 | 无图形界面运行、随系统启动、可被本机或远程控制 |
| P0-9 | 许可合规 | MIT 许可与依赖许可清单 |
| P0-10 | 播放列表与文件分享 | 清单级与文件级分享；仅分享内容可被对端浏览与下载；支持下载整个清单或单个文件 |

### 3.2 P1（补强，不阻断闭环）

- 批量传输与多任务并发调度。
- 传输完成后自动触发元数据同步。
- 清单级播放进度（整个清单作为一条队列的进度）在设备间同步。
- 移动端媒体通知、耳机按键、投送到其他终端播放。
- 库内全文检索、按标签筛选。

### 3.3 明确不做（避免歧义）

- 不提供在线音乐曲库、不提供音频文件的分发市场。
- 不提供音视频转码、音效处理、音频编辑。
- 不提供用户账号体系；设备身份由本机生成，凭据仅用于配对与传输。
- 不把播放位置或音频内容上传到任何中心化服务做长期存储（中继仅做必要时段的转发缓冲）。

## 4. 角色、对象与状态

### 4.1 角色

| 角色 | 说明 |
|---|---|
| 本机用户 | 操作当前终端的用户，对本地音频库拥有完全权限 |
| 对端设备 | 已配对或待配对的其他终端 |
| 中继服务 | 在无法直连时转发数据，不具备读取音频内容以外的能力 |
| 同步源 | MusicBrainz、Last.fm / ListenBrainz、本地开源播放器库文件 |

### 4.2 核心对象与关键字段

| 对象 | 关键属性 |
|---|---|
| 音频库 | 根目录列表、是否包含子目录、排除规则 |
| 被管理目录 | 绝对路径、是否递归、清单标识、最后扫描时间 |
| 音频文件 | 路径、文件名、大小、修改时间、时长、内容指纹、元数据记录引用、文件级分享开关 |
| 播放清单 | 所属目录、条目有序列表、排序规则、状态、最后修改时间、清单级分享开关 |
| 播放位置 | 文件引用、清单引用、已播秒数、是否播完、更新时间 |
| 设备 | 设备标识、显示名、平台、网络可达方式、配对状态、信任状态 |
| 传输任务 | 源设备、目标设备、文件引用、方向、已传输字节、状态、失败原因 |
| 元数据记录 | 标题、艺人、专辑、专辑艺人、曲序、年份、流派、封面、来源、置信度、确认状态 |

### 4.3 状态机

**传输任务**

| 状态 | 可进入的操作 | 允许的下一状态 |
|---|---|---|
| 排队中 | 取消 | 传输中、已取消、失败 |
| 传输中 | 暂停、取消 | 已暂停、已完成、失败、已取消 |
| 已暂停 | 继续、取消 | 传输中、已取消 |
| 已完成 | 打开、删除本地副本 | 终态 |
| 失败 | 重试、取消 | 排队中、已取消 |
| 已取消 | 重新创建 | 终态 |

**设备**

| 状态 | 说明 | 允许的下一状态 |
|---|---|---|
| 已发现 | 局域网内被发现，尚未配对 | 待确认、离线、已阻止 |
| 待确认 | 已发起配对，等待对方确认 | 已配对、已拒绝、已过期 |
| 已配对 | 可发起传输，是否需要接收方确认见 4.4 | 离线、已阻止、已解除 |
| 离线 | 当前不可达 | 已配对、已发现 |
| 已阻止 | 不接收其发现广播与传输请求 | 已发现 |

**播放清单**

| 状态 | 说明 |
|---|---|
| 生成中 | 首次扫描或大规模变更后的构建过程 |
| 就绪 | 可播放 |
| 已完成 | 清单内所有文件均已播完（仅作为展示状态，仍可播放） |
| 失效 | 所属目录被删除、移动或不可访问 |

**元数据记录**

| 状态 | 说明 |
|---|---|
| 未同步 | 仅有内嵌标签 |
| 已同步 | 已由某一同步源补全并通过校验 |
| 待确认 | 存在多个候选或与现有标签冲突，需用户裁决 |
| 已确认 | 用户已手动选定，不再被自动同步覆盖 |

### 4.4 权限矩阵

| 操作 | 本机用户 | 已配对设备 | 未配对设备 |
|---|---|---|---|
| 读取本地音频库 | 允许 | 仅可浏览本端已分享的清单与文件（见 FR-11） | 不允许 |
| 写入本地音频库 | 允许 | 仅在接收方确认后允许 | 不允许 |
| 删除本地音频文件 | 允许（需二次确认） | 不允许 | 不允许 |
| 发起传输（推送） | 允许，推送内容需已开启分享 | 允许，推送内容需已开启分享 | 不允许 |
| 发起传输（拉取） | 允许，仅可拉取对端已分享的内容 | 允许，仅可拉取对端已分享的内容 | 不允许 |
| 修改播放位置 | 允许 | 仅对其自身播放生效 | 不允许 |
| 触发元数据同步 | 允许 | 不允许（只能同步自身库） | 不允许 |
| 开启/关闭分享 | 允许 | 不允许 | 不允许 |
| 解除配对 / 阻止设备 | 允许 | 不允许 | 不允许 |

分享开关默认关闭；用户需在清单或文件上显式开启分享后，对应内容才对已配对设备可见与可下载。分享规则见 FR-11。

## 5. 核心流程

### 5.1 首次启动到可播放

1. 启动后展示快速引导：选择音频库根目录 → 选择是否递归包含子目录 → 选择是否立即扫描。
2. 扫描完成，为每个被管理目录生成播放清单。
3. 用户打开任一清单，播放器默认从清单第一首开始播放。

### 5.2 跨终端传输一次音频

1. A 端在库中选中一个或多个已开启分享的音频文件或清单，选择「发送到设备」（推送）。
2. A 端在已发现/已配对设备中选择目标 B。
3. 若 A、B 同处一个局域网且可直连 → 建立直连传输。
4. 若无法直连 → 自动切换为经中继转发，用户在界面上能看到「经中继」标识。
5. 若 B 当前离线 → 任务进入「排队中」，待 B 上线后自动开始。
6. 传输完成后：B 端在目标目录写入文件并校验；所属目录的清单被更新；B 端提示新文件已到达。
7. 出现同名文件、空间不足或校验失败时，按第 7 章共享规则处理。

> 注意：推送的内容必须已开启分享（清单级或文件级）。未开启分享的内容不可通过推送发送。

### 5.3 打开清单续播

1. 用户打开一个清单。
2. 播放器读取该清单的续播点（上次暂停的文件与秒数）。
3. 自动播放该文件，并从续播点开始。
4. 播放过程中，位置被持续记录；暂停、退出、切换曲目时立即落盘。

### 5.4 元数据同步

1. 用户在设置中选择启用的同步源及其优先级。
2. 用户对全部库或选中范围发起同步。
3. 系统以「内嵌标签 + 音频指纹」为基础识别文件，向同步源查询候选。
4. 命中唯一且不与已确认记录冲突 → 直接补全并标记「已同步」。
5. 命中多个候选或与现有标签冲突 → 标记「待确认」，等待用户裁决。
6. 已完成同步的记录写入本地元数据存储，并在各终端之间随文件传输一并携带（见 FR-07）。

### 5.5 浏览与下载对端分享内容

1. 本端用户进入「设备」页，选择一个已配对且在线的设备，选择「浏览分享」。
2. 本端向对端请求其已分享的清单与文件列表。
3. 对端返回已开启分享的清单（含清单名、文件列表与元数据摘要）和已单独分享的文件。
4. 本端用户选择下载目标：
   - 「下载整个清单」→ 批量创建拉取任务，拉取该清单内全部文件。
   - 「下载单个文件」→ 创建单个拉取任务。
5. 传输按 FR-06 规则执行（直连优先、中继兜底、断点续传、离线排队）。
6. 传输完成后，文件落盘到接收目录，所属目录的清单按 FR-02 自动更新。
7. 若对端在浏览或下载过程中关闭了分享或离线，未完成的任务按 FR-06 异常规则处理。

### 5.6 分享交互流程

以下流程描述用户在本端与对端之间的逐操作交互。每个步骤标注「用户动作」「系统响应」「状态变化」。

#### 5.6.1 开启清单级分享

| 步骤 | 用户动作 | 系统响应 | 状态变化 |
|---|---|---|---|
| 1 | 在清单列表或清单详情页，点击「分享」开关 | 弹出确认对话框，展示清单名、文件数量、总大小，并提示「开启后该清单内全部文件对已配对设备可见与可下载」 | — |
| 2 | 点击「确认开启」 | 开关切换为开启状态；清单条目标记分享图标 | 该清单的清单级分享开关置为「开」；清单内所有文件对已配对设备立即可见 |
| 3 | — | 若当前无已配对设备，界面提示「暂无已配对设备，分享将在设备配对后自动生效」 | 分享状态保留 |
| 4 | — | 若已有已配对设备且在线，下次对端浏览时该清单出现在分享列表中 | 对端可见列表实时更新 |

#### 5.6.2 关闭清单级分享

| 步骤 | 用户动作 | 系统响应 | 状态变化 |
|---|---|---|---|
| 1 | 在已开启分享的清单上，点击「分享」开关关闭 | 弹出确认对话框，提示「关闭后该清单不再对其他设备可见；正在进行的下载任务将被中断；已下载到其他设备的本地副本不受影响」 | — |
| 2 | 点击「确认关闭」 | 开关切换为关闭状态；分享图标消失 | 该清单的清单级分享开关置为「关」；清单内所有文件对已配对设备不再可见（除非文件级分享单独开启） |
| 3 | — | 若有正在进行的该清单文件的拉取任务，任务转为「失败」并标注原因「分享已关闭」 | 受影响的传输任务状态变为「失败」 |
| 4 | — | 对端正在浏览的页面若包含该清单，该清单从列表中移除 | 对端可见列表实时更新 |

#### 5.6.3 开启/关闭文件级分享

| 步骤 | 用户动作 | 系统响应 | 状态变化 |
|---|---|---|---|
| 1 | 在文件列表或文件详情页，点击该文件的「分享」开关 | 若该文件所属清单已开启清单级分享，提示「该清单已开启分享，此文件已对端可见，无需单独开启」 | 无变化 |
| 2a | （清单未分享时）点击「分享」开关开启 | 开关切换为开启状态；文件标记分享图标 | 该文件的文件级分享开关置为「开」；对已配对设备可见 |
| 2b | （清单未分享时）点击「分享」开关关闭 | 开关切换为关闭状态；分享图标消失 | 该文件的文件级分享开关置为「关」；对已配对设备不再可见 |
| 3 | — | 若有正在进行的该文件拉取任务且分享被关闭，任务转为「失败」并标注「分享已关闭」 | 受影响的传输任务状态变为「失败」 |

#### 5.6.4 对端浏览已分享内容

| 步骤 | 用户动作 | 系统响应 | 状态变化 |
|---|---|---|---|
| 1 | 进入「设备」页，选择一个已配对且在线的设备，点击「浏览分享」 | 向对端发送浏览请求 | — |
| 2 | — | 对端校验设备配对状态：已配对 → 返回分享列表；未配对或已阻止 → 返回拒绝 | — |
| 3 | — | 对端返回数据：已开启清单级分享的清单（含清单名、文件数量、总大小、元数据摘要列表）和已开启文件级分享但不在已分享清单内的文件 | 本端展示分享浏览页 |

#### 5.6.5 下载整个清单

| 1 | 在分享浏览页，点击某清单的「下载全部」按钮 | 弹出确认，展示清单名、文件数量、总大小、目标接收目录，并提示同名文件冲突处理策略（默认「跳过并标记冲突」，见 7.2） | — |

#### 5.6.7 分享状态变更对进行中任务的影响

| 触发事件 | 影响范围 | 系统响应 | 状态变化 |
|---|---|---|---|
| 源端关闭清单级分享 | 该清单内所有正在进行的拉取任务 | 未完成任务转为「失败」，标注「分享已关闭」；已完成的文件不受影响 | 传输任务 → 失败 |

## 6. 功能需求

### FR-01 本地音频库与目录扫描

- **目的**：让用户以文件夹形式管理音频，并作为清单、播放、传输、元数据的共同基础。
- **触发**：用户在设置中新增/移除库根目录；或目录内容发生变化；或用户手动触发重新扫描。
- **处理规则**：
  1. 扫描识别音频文件按扩展名白名单判定；白名单为：`.mp3`、`.flac`、`.ogg`、`.oga`、`.opus`、`.m4a`、`.aac`、`.wav`、`.ape`、`.wv`、`.mka`。用户可在设置中增减。

     > 说明：白名单中的 `.ape`、`.wv` 在 P0 阶段仅纳入库管理与清单，播放能力以解码组件实际支持为准（见 FR-03）；若不可解码则在清单中标记为不可播放。是否引入补充解码器以支持播放，待 T21 验证后决定（见开发计划 R1）。
  2. 默认不递归子目录；用户可按根目录开启递归。开启递归时，每个子目录各自生成独立清单。
  3. 扫描忽略隐藏文件与系统目录；排除规则可由用户以路径模式补充。
  4. 目录内容变化（新增、删除、重命名、移动）通过文件监听自动同步到清单；监听不可用时回退为手动/定时扫描。
  5. 扫描结果以文件路径为唯一标识；路径变化视为「删除 + 新增」。
- **结果与状态变化**：被管理目录与其清单被创建/更新/标记失效；库统计对外可见。
- **异常与边界**：
  - 目录不可访问（权限、已拔出、已卸载）：该目录的全部清单标记「失效」，其余目录不受影响。
  - 扫描中断：已完成的目录保持有效，未完成部分在下次扫描继续。
  - 无音频文件的目录：不生成空清单，仅在目录树中展示。
  - 符号链接与循环引用：不作为独立目录处理，避免重复与死循环。

### FR-02 播放清单

- **目的**：每个目录对应一个可播放、自动维护的有序列表，免除手工建单。
- **触发**：目录被纳入管理、目录内容变化、用户手动调整。
- **处理规则**：
  1. 一个被管理目录对应且仅对应一个清单。
  2. 排序规则（规范定义，供全产品唯一引用）：默认按文件名升序；比较前剥离扩展名；比较时不区分大小写；文件名中的连续数字按数值比较（即自然排序，`track2` 排在 `track10` 之前）。
  3. 用户可切换为「按文件修改时间升序」或「按内嵌曲序标签」；切换后仅影响该清单，并记录为清单的当前排序规则。
  4. 手动排序（拖拽）一旦发生，该清单进入「手动顺序」模式，不再随目录变化自动重排；新增文件追加到末尾。
  5. 清单中的条目在被引用的文件被删除或移出库时自动移除。
- **结果与状态变化**：清单状态在「生成中 / 就绪 / 已完成 / 失效」之间切换；排序规则被持久化。
- **异常与边界**：
  - 空清单：目录无音频文件时不创建清单。
  - 超大规模目录：清单分批构建，构建期间可先播放已完成部分。
  - 文件损坏或不可解码：条目保留但标记为不可播放，播放到该条目时自动跳过并提示。
  - 清单文件损坏：由目录内容重新生成，丢失手动顺序并以默认排序恢复。

### FR-03 内置音频播放器

- **目的**：无需依赖外部软件即可完成播放，使播放位置可被本产品完整掌握。
- **触发**：用户打开清单或单个文件。
- **处理规则**：
  1. 播放器为内置、开源、且许可与 MIT 兼容的组件；选型为 Symphonia（MIT 许可，纯 Rust 音频解码库）用于解码，平台原生输出（Windows: WASAPI、Android: AAudio、Linux: PulseAudio/PipeWire）。选型约束见 FR-10。
  2. 支持能力：播放/暂停、上一首/下一首、进度跳转、音量、静音、单曲循环/列表循环/随机播放。
  3. 支持的音频格式以组件实际支持为准，并在发布时对外公布列表；不支持的格式在清单中标记为不可播放。白名单与可播放范围可存在差异：文件可被管理但不可播放（如 P0 阶段的 `.ape`、`.wv`，见 FR-01）；此类条目保留在清单中，播放到该条目时自动跳过并提示。
  4. 播放清单默认从续播点开始（见 FR-04）；从单个文件打开时，等价于以该文件所在清单为上下文并定位到该文件。
  5. Linux 服务模式下无界面，播放器逻辑与播放位置记录保持一致，控制方式见 FR-08。
- **结果与状态变化**：当前播放条目、播放状态（播放中/暂停/停止）对外可见。
- **异常与边界**：
  - 输出设备被占用或不可用：暂停并提示，保留位置，不丢失进度。
  - 音频设备热插拔：暂停并提示，恢复后由用户决定是否继续。
  - 不支持的文件：跳过并记录到「跳过记录」，不中断整条清单。

### FR-04 播放位置记忆与续播

- **目的**：长音频中断后无需重新定位。
- **触发**：打开清单或文件；播放过程中的位置变化；暂停、退出、切换曲目、被系统中断。
- **处理规则**：
  1. 记录粒度：以「清单 + 文件」为键记录已播秒数；同时记录该清单当前正在播放的条目，作为该清单的续播点。
  2. 落盘时机：播放中每 5 秒落盘一次、暂停时立即落盘、退出应用或切换到其他条目时立即落盘。
  3. 恢复规则：打开清单时定位到该清单的续播点条目与秒数，并自动开始播放。
  4. 完成与重置规则：
     - 若已播秒数达到文件总时长，或剩余时长小于 5 秒，则该文件标记为「已播完」，下次从该文件开头播放。
     - 用户手动把进度拖回开头并播放，视为主动重置，清除该文件的续播点。
     - 用户删除文件或将其移出库时，对应记录一并删除。
  5. 同一账号模型不存在；播放位置仅属于当前设备，不默认跨设备同步（跨设备同步属 P1）。
- **结果与状态变化**：续播点被持久化；清单可展示「已完成 / 未完成」标记。
- **异常与边界**：
  - 位置记录文件损坏或版本不兼容：丢弃记录并从文件开头开始，不阻断播放。
  - 文件在记录后被替换（内容变化但路径相同）：以文件大小与修改时间校验，不一致则丢弃该文件的位置记录。
  - 时钟回拨或系统时间异常：位置记录按相对时长校验，异常值被忽略。
  - 应用被强制结束时未落盘的最大丢失量，等于第 2 条定义的落盘间隔。

### FR-05 设备发现与配对

- **目的**：让传输的发起者能可靠地找到目标设备。
- **触发**：应用启动；用户进入「设备」页；用户手动添加设备。
- **处理规则**：
  1. 局域网内自动发现：同一网络内的已安装本软件设备相互可见，展示设备名与平台。
  2. 跨网络发现：通过用户手动输入设备标识或配对信息添加；不使用中心化账号目录。
  3. 配对：任一端发起，另一端确认后建立配对关系；配对后设备进入「已配对」，可免重复确认发起传输（是否免确认见第 4 条）。
  4. 接收确认策略由接收方设定，可选「每次确认」「仅首次确认」「信任设备免确认」；默认「每次确认」。
  5. 分享范围：默认不对任何设备分享任何清单或文件。用户在清单或文件上显式开启分享后，对应内容才可被已配对设备浏览与拉取。分享规则见 FR-11。
  6. 设备可被解除配对或阻止；阻止后不再接收其发现广播与传输请求。
- **结果与状态变化**：设备在 4.3 定义的状态间流转；配对与分享设置被持久化。
- **异常与边界**：
  - 同名设备：以设备标识区分，界面同时展示平台与标识后缀。
  - 配对请求超时或对方离线：请求进入「已过期」，可重新发起。
  - 网络切换（Wi-Fi 与有线、公共网络）：已配对关系保留，发现结果实时刷新。
  - 设备标识被复制到另一台机器：允许存在，但配对关系需重新建立。

### FR-06 P2P 音频传输

- **目的**：在多终端之间可靠搬运音频文件，且不依赖用户手工拷贝。
- **触发**：用户在库中选中已开启分享的文件或清单并选择目标设备（推送）；或在设备页浏览对端已分享内容并选择下载（拉取）。
- **处理规则**：

  1. **分享前置条件（规范定义，唯一引用）**：无论推送还是拉取，传输的内容必须已开启分享（清单级或文件级，见 FR-11）。推送未分享的内容被拒绝并提示；拉取仅能获取对端已分享的内容。

  2. **路径选择（规范定义，唯一引用）**：优先尝试局域网直连；直连不可达时自动切换到中继转发。用户可强制「仅直连」（此时跨网络传输不可用）。当前使用直连还是中继，在任务详情中可见。

  3. **传输方向**：支持推送（本机 → 对端）与拉取（对端 → 本机）。拉取仅能访问对端已开启分享的清单与文件。

  4. **断点续传**：任务中断（网络断开、应用退出、设备离线）后，任务转为「已暂停」；恢复可达后从已完成的字节位置继续，不重新开始。

  5. **离线排队**：目标设备离线时任务保持「排队中」，在其上线后自动开始；排队任务可被取消。

  6. **完整性校验**：传输完成后由接收方校验内容一致性，校验失败按「失败」处理并允许重试。校验方式为 SHA-256 哈希比对，哈希值由发送方在传输前计算并随传输元数据一并发送。

  7. **落地位置**：接收方决定落盘目录——可选「固定的接收目录」或「按来源目录结构还原」。来源目录不存在时自动创建。

  8. **并发与带宽**：并发任务数量与带宽限制可配置，用于避免占满家庭网络。默认并发 3 个任务，带宽不限（0 = 不限）；用户可在设置中调整。

  9. **清单联动**：文件落盘且校验通过后，接收方所属目录的清单按 FR-02 自动更新。

  10. **元数据携带**：随文件一并携带发起端已有的元数据记录与确认状态，接收方据此减少重复同步。

- **结果与状态变化**：传输任务在 4.3 定义的状态间流转；接收方库内容与清单同步更新。
- **异常与边界**：
  - 同名文件冲突：按 7.2 处理。
  - 磁盘空间不足：任务失败并提示所需空间与可用空间；不写入半成品文件；已接收的部分可选择保留以便续传。
  - 传输中两端网络同时不可达：任务暂停；超出 7 天保留期限后清理未完成的数据。
  - 中继不可用：若无法直连且中继不可用，任务失败并明确提示原因，不静默卡住。
  - 文件在传输中被源端修改或删除：任务失败并提示，需重新发起。
  - 分享在传输中被关闭：任务转为失败并提示「分享已关闭」，不继续传输未完成部分。
  - 两端同时互相发送同名文件：各自按 7.2 处理，不自动互相覆盖。

### FR-07 元数据同步

- **目的**：让同一音频文件在不同终端上呈现一致的、可信的描述信息。
- **触发**：用户对全部库或选中范围发起同步；或按 P1 在传输完成后自动触发。
- **处理规则**：

  1. **基础层**：以内嵌标签（ID3 / Vorbis Comment / FLAC 等）为第一来源；内嵌标签始终保留在本机，不被自动覆盖。

  2. **指纹层**：对缺少足够标签或标签置信度低的文件，使用 Chromaprint 计算本地音频指纹参与匹配，以避免仅凭文件名导致的错误匹配。Chromaprint 以 LGPLv2.1 许可发布，通过独立进程调用方式与 MIT 主体隔离，满足许可兼容性（见 FR-10）。AcoustID 外部查询为可选功能，默认关闭，用户开启后可将本地指纹提交至 AcoustID API 查询识别结果；AcoustID 数据以 CC0 许可发布，查询 API 无需用户凭据但需携带应用标识。

  3. **可用同步源与优先级**（规范定义，唯一引用）：

     | 优先级 | 来源 | 提供内容 |
     |---|---|---|
     | 1 | 内嵌标签与音频指纹 | 标题、艺人、专辑、曲序、封面、时长 |
     | 2 | MusicBrainz | 录音/发行/曲目实体标识、标题、艺人、专辑、曲序、年份 |
     | 3 | Last.fm / ListenBrainz | 标签、流行度、相似信息等辅助字段 |
     | 4 | 本地开源播放器库文件 | 从用户指定的导出文件批量对齐（如 foobar2000、MusicBee、Quod Libet、Clementine 等导出的库或播放列表文件） |

     用户可调整来源顺序或关闭某一来源。

  4. **匹配与冲突**：命中唯一候选且不与「已确认」记录冲突时直接补全；出现多候选或与现有标签冲突时进入「待确认」，由用户裁决。自动同步不覆盖用户已确认的记录。

  5. **字段级结果可见**：每条记录可查看「字段值 + 来源 + 置信度 + 确认状态」，允许逐字段接受或改写。

  6. **离线可用**：无网络时，基础层与本地播放器库文件来源仍可用；外部来源不可用时任务标记为跳过，网络恢复后可重试。

  7. **写回文件的边界**：写回内嵌标签属于对用户文件的修改，默认关闭；开启后需二次确认，并可选择仅更新本产品自身的元数据存储而不改动原文件。

- **结果与状态变化**：元数据记录在 4.3 定义的状态间流转；清单与播放界面的展示随之更新。
- **异常与边界**：
  - 外部来源限流或不可达：任务跳过并保留原状态，支持稍后重试，不阻塞其他文件。
  - 指纹计算失败（文件损坏、格式不支持）：跳过该文件并标记，不中止整体任务。
  - 本地播放器库文件格式无法解析：提示用户并提供支持的导出格式说明。
  - 同名但内容不同的音频：以指纹为准区分，不以文件名合并。

### FR-08 Linux 无图形化服务模式

- **目的**：让 Linux 设备在不运行图形界面的情况下长期承担扫描、清单维护、播放与续播。
- **触发**：以服务方式启动（随系统启动或手动启动）。
- **处理规则**：
  1. 服务模式不加载任何图形界面依赖，可在无显示服务器环境运行。
  2. 启动时自动加载已配置的音频库，按 FR-01 / FR-02 完成扫描与清单维护。
  3. 具备与图形模式一致的传输能力（FR-06）与元数据同步能力（FR-07）。
  4. 具备播放能力：可在无界面下按清单播放，并同样遵循 FR-04 的位置记录与续播规则。
  5. 控制方式：提供本机控制入口（命令行工具 + 本地 Unix Socket 控制通道）用于查询状态、选择清单、播放/暂停、跳转、触发同步与传输。P0 不提供网络控制接口，网络远程控制列为 P1 候选。
  6. 日志与状态：输出可被系统日志收集的结构化日志；关键状态（当前清单、当前文件、播放位置、传输任务）可被查询。
  7. 随系统启动、崩溃后自动重启由系统服务管理器承担；服务异常退出不得损坏播放位置与清单数据。
  8. 权限：以最小权限运行；对音频库目录只要求读写所必需的范围；不以 root 运行。
- **结果与状态变化**：服务状态、当前播放状态、传输任务状态可被外部查询。
- **异常与边界**：
  - 无音频输出设备（纯服务器）：播放相关操作返回明确错误，扫描、清单、传输、元数据同步不受影响。
  - 音频库位于未挂载的外部存储：该目录清单标记「失效」，其余功能不受影响。
  - 配置缺失或损坏：以默认配置启动并记录明确日志，不静默退出。
  - 多实例同时运行：后启动的实例检测到已有实例在运行并退出，避免数据竞争。

### FR-09 设置与本地配置

- **目的**：把分散在各功能中的可配置项收拢到一处，并保证跨平台一致。
- **可配置项**（均为本机生效）：

| 分组 | 配置项 |
|---|---|
| 音频库 | 根目录列表、是否递归、排除规则、音频扩展名白名单 |
| 清单 | 默认排序规则、是否自动维护 |
| 播放 | 循环模式、音量、续播开关、位置落盘间隔 |
| 传输 | 接收目录、来源目录结构还原开关、并发数、带宽限制、仅直连开关、中继开关 |
| 设备 | 已配对设备、接收确认策略、已阻止设备 |
| 分享 | 清单级分享开关（按清单）、文件级分享开关（按文件）、分享元数据摘要包含的字段范围 |
| 元数据 | 同步源开关与优先级、是否写回文件标签、自动同步开关 |
| 通用 | 开机/随系统启动、语言、日志级别、数据存储位置 |

- **处理规则**：设置在本机持久化；除明确标注为可同步的项外，不随文件传输同步到对端。
- **异常与边界**：配置项非法时回退到默认值并记录日志；数据存储位置不可写时，功能降级并明确提示。

### FR-10 开源许可与合规

- **目的**：以 MIT 协议开源，并保证整体可分发的许可兼容性。
- **处理规则**：
  1. 本产品自身代码以 MIT 协议发布，随发行包提供 LICENSE 文件。
  2. 所有内置组件、第三方依赖、外部服务的使用，其许可必须与 MIT 分发兼容；不引入与 MIT 冲突的强传染性许可组件，除非以独立进程或可选安装方式隔离。
  3. 发布物提供依赖许可清单（含名称、版本、许可、来源），并在依赖更新时同步更新。
  4. 音频指纹组件 Chromaprint（LGPLv2.1）通过独立进程调用方式与 MIT 主体隔离，不静态链接，满足分发兼容性；AcoustID 数据以 CC0 许可发布；MusicBrainz 数据以 CC0 许可发布，查询 API 需遵守其速率限制并携带 User-Agent 标识；Last.fm API 需应用级 API Key，用户无需个人凭据；ListenBrainz API 可匿名访问。以上均通过评估，许可兼容。
  5. 元数据来源的使用需遵守各来源的服务条款与署名要求；对要求署名的来源，在界面或文档中体现署名。

- **异常与边界**：新增依赖引入许可冲突时，构建流程应阻断并提示（构建流程属实现范畴，此处仅定义合规要求）。

### FR-11 播放列表与文件分享

- **目的**：让用户有选择地把播放清单或单个音频文件开放给已配对设备浏览与下载，作为 P2P 传输的前置条件。
- **触发**：用户在清单或文件上开启/关闭分享；已配对设备发起浏览或下载请求。
- **处理规则**：

  1. **分享粒度**：支持「清单级分享」与「文件级分享」两种。开启清单级分享后，该清单内所有文件对已配对设备可见且可下载；开启文件级分享后，仅该文件对已配对设备可见且可下载。

  2. **默认状态**：所有清单与文件默认不分享。用户需显式开启分享后，对应内容才对已配对设备可见。

  3. **两级分享关系（规范定义，唯一引用）**：清单级分享开启时，清单内所有文件自动对端可见，无需逐个开启文件级分享；清单级分享关闭但个别文件级分享单独开启时，仅这些文件对端可见。同一文件不因两种分享同时开启而重复展示。

  4. **对端浏览**：已配对设备可浏览本端已分享的清单（含清单名、文件列表与元数据摘要）和已单独分享的文件。浏览请求返回的是列表与摘要，不包含音频内容本身。未分享的内容对端完全不可见。

  5. **下载方式**：对端可选择「下载整个清单」（批量拉取清单内全部文件，按 FR-06 批量创建传输任务）或「下载单个文件」（创建单个拉取任务）。下载传输按 FR-06 规则执行。

  6. **分享状态变更**：分享开启或关闭后实时生效。关闭分享不影响对端已下载的本地副本；但正在进行的传输任务按 FR-06 异常规则处理（分享在传输中被关闭 → 任务失败）。

  7. **分享元数据**：被分享的清单与文件在浏览时附带其元数据记录摘要（标题、艺人、专辑、时长等），便于对端判断是否需要下载。元数据摘要不包含封面等大尺寸资源，需对端另行请求。

  8. **分享范围限定**：分享仅对已配对设备生效；未配对设备不可浏览或下载。P0 不支持「按设备粒度差异化分享」，全部已配对设备可见相同内容；按设备差异化分享列为 P1 候选。

- **结果与状态变化**：清单与文件的分享开关被持久化；对端可见的分享列表随之更新。
- **交互流程**：见 5.6 节，覆盖开启/关闭分享、对端浏览、下载清单与单个文件、以及分享状态变更对进行中任务的影响共 7 个子流程。
- **异常与边界**：
  - 文件在分享开启后被删除或移出库：该文件从分享列表中移除，对端浏览时不再显示。
  - 清单在分享开启后失效（目录不可访问）：该清单标记为不可用，对端浏览时展示「不可用」状态，不返回文件内容。
  - 分享开启但无已配对设备：分享状态保留，在设备配对后自动生效。
  - 清单级分享开启后新增文件到该目录：新文件自动纳入该清单的分享范围。
  - 清单级分享开启后从该目录移除文件：被移除的文件自动从分享范围消失，不影响其他文件。

## 7. 共享规则与异常

### 7.1 文件名与排序规则（规范定义）

- 清单排序：见 FR-02 第 2 条，全产品唯一引用。
- 文件名比较：剥离扩展名、不区分大小写、数字按数值比较。
- 跨平台文件名：目标文件系统不支持源文件名中的字符时，按 7.2 的冲突处理流程提示用户改名，不静默改名。

### 7.2 同名冲突处理（规范定义）

当接收端目标位置已存在同名文件时，提供以下处理，默认「跳过并标记冲突」：

| 选项 | 行为 |
|---|---|
| 跳过并标记冲突 | 不写入；任务标记为冲突，进入待处理列表 |
| 覆盖 | 覆盖目标文件；需二次确认；覆盖前将被覆盖文件移入本产品的回收位置 |
| 保留两者 | 以带序号的新名称写入，并在界面上标注来源设备 |
| 逐项处理 | 对多文件任务逐个询问 |

被移入回收位置的文件保留 30 天后自动清理，用户可手动清空回收位置。

### 7.3 进度落盘与恢复（规范定义）

- 落盘时机与恢复规则见 FR-04，全产品唯一引用。
- 播放位置为「可丢失数据」：应用崩溃最多丢失一个落盘间隔内的进度。
- 清单与元数据为「不可静默丢失数据」：写入需保证原子性（写入过程崩溃后不得出现半写状态导致清单损坏）。

### 7.4 网络与离线（规范定义）

- 直连优先、中继兜底，见 FR-06 第 1 条。
- 设备离线不阻止用户创建任务，任务进入排队；排队任务数量上限为 100，超出时拒绝新建并提示。
- 所有网络失败都必须给出可理解的原因（未联网、对端离线、中继不可用、被对方拒绝、存储不足），不出现无提示的长时间等待。

### 7.5 存储与配额

- 本产品的数据存储位置由用户可配置；默认位置按平台分别为：Windows `%APPDATA%/AudioMesh`、Android 应用内部存储 `files/AudioMesh`、Linux `~/.local/share/AudioMesh`。
- 传输临时数据、被覆盖文件的回收位置、日志各占用独立空间，分别可配置上限。默认上限：传输临时数据 500 MB、回收位置 1 GB、日志 200 MB。
- 达到上限时的策略：优先清理已完成的临时数据与超期回收文件；不删除用户的音频文件。

### 7.6 隐私与数据边界

- 音频内容仅在发起端、接收端与（必要时）中继之间流转；中继不作为长期存储。
- 元数据同步的上行内容默认为文件识别信息，最小化字段范围为：音频指纹哈希、时长、标题、艺人。不包含文件内容与文件路径。用户可在设置中完全关闭外部来源查询，此时仅使用基础层（内嵌标签）与本地播放器库文件来源，不上传任何数据。
- 日志默认不记录完整文件路径与音频内容，仅记录必要的标识与结果。

- **Android**：目录访问受分区存储限制，音频库需通过 Storage Access Framework（SAF）授权持久化 URI；后台传输与播放通过前台服务（Foreground Service）声明 `mediaPlayback` 与 `dataSync` 类型保持运行；首次配置时引导用户将应用加入电池优化白名单，用户拒绝后降级为仅前台传输与播放。
- **Windows**：随系统启动通过注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 或任务计划程序实现（用户可选）；托盘常驻提供快速访问；局域网发现首次运行时引导用户允许防火墙例外（UDP 广播端口）。
- **Linux**：音频输出依赖系统中的 PulseAudio 或 PipeWire 服务；服务模式下需以能访问音频服务的用户身份运行（不使用 root，通常以安装应用的用户运行 systemd user service）；无音频服务的纯服务器环境可运行扫描、清单、传输、元数据同步，播放功能返回明确错误。

## 10. 假设清单

以下假设在 P0 阶段作为设计前提，将在首次用户测试中验证。

| 编号 | 假设 |
|---|---|
| A1 | 用户主要在家庭或办公局域网内进行跨终端传输，跨网络为次要场景 |
| A2 | 音频库以用户自有文件为主，文件总量与目录深度处于桌面与移动设备可承受范围内 |
| A3 | 用户可接受「接收方确认」作为传输默认策略，并愿意为信任设备一次性放宽 |
